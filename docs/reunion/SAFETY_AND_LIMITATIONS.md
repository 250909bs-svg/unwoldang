# MZ큐피트 재회운 안전 정책과 한계

## 1. 최우선 원칙

재회운은 상대에게 연락할 권리를 만들어 주지 않는다. 상대의 명시적 의사, 법적 제한, 신체·정서적 안전이 모든 명리 신호와 상품 경험보다 우선한다.

제품은 상담·의료·법률·수사·긴급 구조 서비스가 아니다. 즉각적인 위험이 있으면 리포트를 계속 보지 말고 대한민국에서는 112 또는 119 등 지역의 공식 긴급기관과 신뢰할 수 있는 사람에게 도움을 요청해야 한다.

## 2. 필수 시작 조건

다음 조건을 모두 확인하지 못하면 `ANALYSIS_BLOCKED`다.

- 성인 확인
- 민감한 관계·출생정보 처리 동의
- 본인과 상대 정보 사용 권한 확인

이 확인은 법률 자문이나 개인정보 처리 적법성 검토를 대신하지 않는다. 운영 전 실제 동의문, 개인정보 처리방침, 제3자 정보 처리 근거를 한국 개인정보보호법 관점에서 별도 검토해야 한다.

## 3. SafetyGate 상태

### `ANALYSIS_BLOCKED`

현재 코드에서 다음 위험 신호는 분석과 모든 연락 조언을 차단한다.

- 폭력
- 위협
- 스토킹 또는 신고·접근 제한 상황
- 강압적 통제·감시
- 자해를 조건으로 한 관계 압박

이 상태에서는 연락 날짜, 채널, 첫 문장, 메시지 수정안, 답장 대응 트리를 제공하지 않는다.

### `CONTACT_PROHIBITED`

다음은 연락을 금지하고 시기·문구를 숨긴다.

- 상대의 명시적 비접촉 요구
- 상대 차단 또는 상호 차단
- 다른 번호·계정·지인을 통한 차단 우회 시도
- 상대의 현재 관계를 방해하려는 목적
- 금전 착취 신호

명리 점수가 높아도 이 판정은 바뀌지 않는다.

### `PREPARATION_REQUIRED`

즉시 연락보다 준비가 먼저인 경우다.

- 반복된 이별 원인이 바뀌지 않음
- 무응답을 받아들일 준비가 안 됨
- 자신의 책임을 정리하지 못함
- 경계를 존중할 준비가 부족함
- 정서적 준비도가 낮음
- 최근 7일 이내 갈등성 연락이 있었음

이 상태에서는 연락 구간과 완성 메시지를 제공하지 않고 변화 증거와 중단 규칙을 제시한다.

### `CONTACT_ELIGIBLE`

위 조건을 모두 통과한 경우에도 “연락 권장”이나 “재회 가능 확정”이 아니다. 단 한 번의 낮은 압력 연락을 검토할 수 있다는 조건부 상태다. 거절, 차단, 무응답, 분노, 위협이 확인되면 즉시 종료한다.

## 4. 금지되는 제품 행동과 문구

- 차단 우회 방법 제공
- 반복 연락·잠복·지인 동원 조언
- 상대의 현재 관계를 깨뜨리는 조언
- 죄책감, 자해, 금전, 협박을 이용한 문구
- “무조건 재회”, “100% 연락”, “정확한 날짜” 같은 보장
- “상대는 아직 사랑한다”처럼 확인 불가능한 내면 확정
- 불안을 키워 추가 결제를 유도하는 문구
- 전문가 검수가 없는데 검수 완료로 표시

## 5. 연락 전략의 중단 규칙

연락 전략이 허용된 경우에도 다음 중 하나면 즉시 중단한다.

- 상대가 연락하지 말라고 명시함
- 차단 또는 신고·법적 제한이 확인됨
- 1회 연락 후 7일 동안 무응답
- 모욕·위협·분노가 나타남
- 사용자가 무응답을 견디지 못해 반복 연락하려 함
- 안전 신호가 새로 발견됨

“좋은 월운”이나 높은 지표는 중단 규칙의 예외가 아니다.

## 6. 개인정보 현재 상태

재회운은 출생정보, 관계 이력, 차단·폭력 여부, 메시지 초안 등 민감도가 높은 정보를 다룬다. 현재 운영 기반은 Firestore이며 결제 원장과 리포트 아카이브를 사용한다.

확인된 현재 한계는 다음과 같다.

- 재회운 전용 데이터 최소화·민감도 등급 스키마가 없다.
- 아카이브는 전체 항목을 `entryJson` 문자열로 보관하므로 실제 포함 필드 인벤토리가 필요하다.
- 사용자용 서버 아카이브 삭제 API와 완전 삭제 증적이 없다.
- 보존 기간, 자동 만료, 백업 삭제 주기가 코드와 운영정책으로 확정되지 않았다.
- 열람·정정·삭제 요청 처리 워크플로가 없다.
- 로컬 기기 기록 삭제는 서버 Firestore 삭제를 의미하지 않는다.
- 상대방 출생정보 등 제3자 정보의 수집 범위와 적법성 검토가 미완료다.

상용 출시 전에 최소 수집, 목적 제한, 보존 기간, 사용자 삭제, 관리자 접근 기록, 침해 대응, 위탁·국외 처리 고지를 확정해야 한다. 이 문서는 법률 자문이 아니다.

## 7. 결제·환불 한계

현재 코드에는 서버 서명 주문, PortOne 결제 확인, 권한 복구와 리포트 접근 token이 있다. 그러나 재회운 전용으로 다음이 완성되었다고 볼 수 없다.

- 결제 취소·환불 API 및 PortOne 상태 동기화
- 생성 전·후 환불 기준
- 중복 결제·실패 생성·지연 생성 CS 절차
- 환불 후 entitlement와 아카이브 접근 회수
- 소비자 고지와 전자상거래 운영 검토

이 항목을 구현·검증하기 전에는 자동 환불 또는 완성된 환불 체계가 있다고 안내하면 안 된다.

## 8. 전문가 워크플로 한계

코드의 “expert” 또는 다중 관점 해석 명칭은 실제 인간 전문가가 건별로 검수했다는 뜻이 아니다. 현재 상태는 다음과 같다.

- 만세력·명리: 내부 규칙 및 회귀 테스트, **외부 명리 전문가 감수 전**
- 자미두수: 미구현·미사용
- 전문가 신청 접수: 미구현
- 전문가 신원·자격 검증: 미구현
- 케이스 배정·SLA: 미구현
- 수정 제안·승인·전자서명·감사 이력: 미구현
- 상담 기록 보존·삭제: 미구현

따라서 “청담 선생 직접 감수”, “20년 전문가 승인”, “시그니처 전략실 배정 완료” 같은 문구를 사용하거나 해당 유료 단계를 판매하면 안 된다. 실제 워크플로가 구현되고 건별 승인 증적이 있어야 표시할 수 있다.

## 9. 계산·콘텐츠 한계

- 14개 지표는 통계적 확률이 아니다.
- 상대가 입력하지 않은 감정·의도·행동은 알 수 없다.
- 상대 출생정보가 없거나 시간이 미상이면 궁합·시주 범위와 신뢰도를 낮춘다.
- 현재 궁합은 정적 원국 중심이며 대운·세운 완전 교차 엔진이 아니다.
- 월운은 절기 단위 넓은 구간이며 일진 추천이 아니다.
- 자미두수는 결과에 포함되지 않는다.
- 외부 전문가 감수와 독립 안전성 평가가 완료되지 않았다.
- 현재 전용 지표 계산은 클라이언트에서 실행되어 서버 권위·변조 방지 구조가 미완성이다.
- 브라우저 상태 유실, 새로고침, 결제 복귀, 다중 기기 복원 시나리오의 운영 검증이 필요하다.

## 10. 출시 전 필수 안전 검증

다음 케이스를 실제 운영 빌드에서 수동·자동으로 검증한다.

1. 폭력 또는 위협 체크 시 분석·문구·시기 모두 차단
2. 비접촉 요구와 상대 차단 시 우회 조언이 전혀 없음
3. 반복 원인 미해결 시 연락 구간이 숨겨짐
4. 상대 출생정보 미상 시 궁합을 생성하지 않고 신뢰도가 낮아짐
5. “100%”, “무조건”, 상대 내면 확정, 정확한 날짜 문구 없음
6. 결제 전 전체 리포트 접근 차단, 로컬 DEV 우회가 운영에서 비활성
7. 사용자별 아카이브 격리
8. 삭제 요청이 Firestore와 파생 데이터·백업 정책까지 연결됨
9. 환불 시 권한 회수와 재접근 정책이 일치
10. 운영 로그에 원문 메시지·출생정보·관계 서술이 불필요하게 남지 않음
