# MZ무당 팩폭 연애운 — 제품 명세

## 목표

`love-reading`의 기존 결제·주문·리포트 보관 호환성을 유지하면서, 상품 진입부터 결과까지 하나의 모바일 웹툰형 상담 경험으로 제공한다.

이 상품은 미래나 상대의 마음을 단정하지 않는다. 사주 원국과 운 흐름에서 확인되는 근거, 다른 해석 가능성, 현실에서 검증할 행동을 한 세트로 제시한다.

## 고객 여정

1. 홈·검색·마이페이지·내비게이션에서 `/detail/love-reading`으로 진입한다.
2. ACT 00–10 티저에서 MZ무당의 대화, 연애 반응 선택, 상품 구성과 샘플 판정을 체험한다.
3. `/form/love-reading`에서 출생 정보, 현재 관계 상태, 연애 질문을 입력한다.
4. 기존 Checkout → Loading → Report 파이프라인을 사용한다.
5. `/report/love-reading`에서 13개 챕터, 12개월 흐름, 메시지 실험, 플래그와 30일 행동 미션을 확인한다.
6. 결제된 결과는 기존 로컬·원격 보관 구조에 남고, 고객은 현재 상태가 반영된 독립 HTML 파일로도 저장할 수 있다.

## 관계 상태 입력 6종

고객에게 노출하는 관계 상태는 아래 여섯 가지다.

| 입력값 | 화면 표시 | 입력 규칙 |
|---|---|---|
| `single` | 솔로 | 관계 기간 선택 |
| `situationship` | 썸 타는 중 | 관계 기간 선택 |
| `dating` | 연애 중 | 관계 기간 필수 |
| `ambiguous` | 관계가 애매함 | 관계 기간 선택 |
| `breakup-reunion` | 이별·재회 고민 | 관계 기간 선택 |
| `married` | 기혼 | 관계 기간 필수 |

`married`는 리포트 도메인에서 장기 관계 분기인 `long-term`으로 변환한다. 나머지 다섯 값은 같은 이름의 도메인 분기로 전달한다. 티저의 연애 반응 선택은 `A | B | C | D`로 저장되어 입력·분석 파이프라인에 함께 전달된다.

## 결과 챕터 13개

1. 너, 연애할 때 딴사람 돼
2. 왜 늘 이런 사람에게 꽂힐까
3. 네가 끌리는 사람
4. 오래 갈 사람은 따로 있어
5. 끌리는 사람 vs 오래 갈 사람
6. 다음 인연에서 볼 분위기
7. 어디서 어떻게 시작될까
8. 지금부터 12개월 연애 흐름
9. 연락에서 네가 놓치는 포인트
10. 지금 관계에 맞는 팩폭
11. 레드 플래그와 그린 플래그
12. 이번엔 이렇게 해야 안 망해
13. 마지막 팩폭

각 챕터는 `팩폭 → 명리 해석 → 현실 장면 → 반대 가능성 → 확인 기준 → 지금 할 행동` 순서로 읽힌다. 5장은 설렘과 지속 가능성 비교, 8장은 12개월 탭, 9장은 메시지 선택, 11장은 행동 플래그, 12장은 기기 저장형 30일 체크리스트를 추가로 제공한다.

## 판정과 원문 근거 계약

- 원국 계산값과 결정론적 엔진 원문은 생성형 AI나 화면 카피가 수정하지 않는다.
- `SajuReportData`가 리포트 어댑터의 단일 원천이다.
- `EvidenceTag`는 `id`, `label`, `value`, `description`, `source`, `sourcePath`, `immutable`과 선택적 `confidence`·`uncertainty`를 보존한다.
- 고객에게 표시할 해석은 그 문장을 가져온 정확한 `sourcePath`와 일치하는 근거만 연결한다. 일치하는 출처가 없으면 다른 원국·관계·시기 근거를 임의로 채우지 않는다.
- 근거 상세에는 원문 라벨·원문 값·설명·출처와, 존재할 경우 신뢰도를 표시한다.
- 고객 대화문에는 엔진 ID, 감사 로그, 계산 메타데이터 같은 내부 문장을 노출하지 않는다. 내부 원문은 근거 상세에서만 보존한다.
- 시간 미상, 경계 시각, 데이터 부족은 확정 표현 대신 불확실성 안내를 노출한다.
- 상대의 속마음, 재회·결혼 확정, 특정 날짜의 사건을 단정하지 않는다.

## 장면 선택 구조

- 전체 장면 자산은 30종이며 `sceneManifest.ts`가 단일 매니페스트다.
- `sceneResolver.ts`는 챕터 후보군에 현재 관계 상태와 파생 문장·시기 신호·위험 신호의 의미 키워드를 합쳐 결정적으로 장면을 고른다.
- `previouslyUsedScenes`를 누적하므로 한 리포트의 13개 챕터에는 서로 다른 장면 13개가 배치된다.
- 장면은 설명 순서와 감정 몰입만 바꾸며 명리 결과나 근거를 바꾸지 않는다.
- 원본 30장과 웹 전달용 60개 파일의 경로·품질 기준은 `docs/mz-love-asset-production.md`를 따른다.

## 접근 제어와 보관

- 개발 중 샘플 리포트는 `DEV`이면서 `localhost`, `127.0.0.1`, `::1`인 경우에만 허용한다.
- 운영 환경에서는 유효한 주문 ID와 구조가 올바르고 서비스 ID가 일치하는 `reportData`가 있어야 리포트를 렌더링한다. 조건이 맞지 않으면 입력 화면으로 돌려보낸다.
- 이 클라이언트 게이트는 심층 방어 수단이다. 결제 확인, 리포트 발급, 원격 보관 쓰기의 최종 권한은 서버에 있다.
- 로컬 보관은 결제된 주문과 리포트 데이터가 있을 때 생성한다. 인증 토큰과 리포트 접근 토큰이 함께 있을 때만 원격 보관을 요청한다.
- HTML 보관본은 체크박스 상태를 복제하고, 접힌 근거와 숨겨진 비교·월별 패널을 펼치며, 메시지 선택지를 정적 해설로 포함한다. 고정 버튼과 조작 UI는 제거하고 이미지를 파일 안에 포함해 독립적으로 열 수 있게 한다.

## 공유와 개인정보

- 연애운 리포트의 공유 버튼은 개인 결과 페이지가 아니라 `/detail/love-reading` 상품 링크를 공유한다.
- 공유 제목과 설명은 고정된 상품 소개 문구만 사용한다.
- 고객 이름, 출생 정보, 관계 상태, 판정 문장, 주문 ID, 리포트 접근 토큰은 공유 데이터에 포함하지 않는다.

## 상용 운영 기준

- 기존 서비스 ID `love-reading`을 유지한다.
- 가격은 `serviceCatalog`의 단일 값을 화면 전체에서 참조한다.
- 미션 체크 상태는 기기 저장소에 저장하며 사주 원본 데이터와 분리한다.
- 모든 캐릭터 이미지는 동일한 성인 캐릭터, 비노출·비공포·무텍스트 기준으로 검수한다.
- 광고 문구에 검증되지 않은 판매량, 후기, 순위 또는 확정적 미래 표현을 넣지 않는다.
- 출시 전 최종 확인 항목은 `docs/mz-love-launch-checklist.md`를 따른다.
